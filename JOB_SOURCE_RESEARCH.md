# Job-source research and coverage limits

Last checked: 2026-11-21. This is an operator-facing assessment, not evidence of a production integration, legal approval, or universal coverage. Do not import a source until its use, retention, attribution and access terms have been reviewed and the owner has approved the specific boards. Never bypass access controls or send applications automatically.

| Source | Official documentation | Current implementation and evidence | Remaining gate |
| --- | --- | --- | --- |
| Greenhouse Job Board | https://docs.greenhouse.io/job-board.html | Per-employer public listing adapter exists; authenticated application submission is not implemented. Tests use mocks. | Board identifiers, terms, worker credentials/scheduler, live staging. |
| Lever postings, global | https://github.com/lever/postings-api | Per-employer public listing adapter, bounded pagination and mock tests. Lever's documented `leverdemo` example returned a JSON response through the page-fetch service; its listings are demo/test material and were **not imported**. | Approved real boards, terms, worker credentials/scheduler, live staging. |
| Lever postings, EU | https://github.com/lever/postings-api | Separate `lever_eu` adapter uses the documented EU host and preserves regional identity; mocked normalization/pagination tests. Lever's documented EU `leverdemo` example returned JSON through the page-fetch service; it was **not imported**. | Approved real EU boards, terms, worker credentials/scheduler, live staging. |
| Ashby Job Postings | https://developers.ashbyhq.com/docs/public-job-posting-api | Per-board public adapter exists; mock tests. | Board identifiers, terms, worker credentials/scheduler, live staging. |
| SmartRecruiters Posting API | https://developers.smartrecruiters.com/reference/posting-api-1 | Per-company public adapter exists with bounded pagination; descriptions are not fetched. Mock tests only. The provider's documented SmartRecruiters example returned a one-item JSON response through the page-fetch service; this was not imported or tested end-to-end in the worker. | Board identifiers, detail-fetch design, terms, worker credentials/scheduler and staging. An empty response must not be assumed to prove a valid board. |
| Workable public account jobs | https://workable.readme.io/reference/jobs-1 | Researched only; **not implemented**. Official docs describe public jobs for an account and optional descriptions. The documentation example could not be fetched through the available page-fetch service. | Verify current API behavior, terms, data shape, pagination/completeness and any required permissions before implementation/production use. |
| Adzuna | https://developer.adzuna.com/docs/search and https://developer.adzuna.com/docs/terms_of_service | Researched only; **not implemented or configured**. Search coverage, access, attribution and commercial licensing are subject to the provider's current terms. | Owner account, credentials, legal/terms review, country and quota validation. |
| Jooble | https://jooble.org/api/about | Researched only; **not implemented or configured**. | Provider access, partner terms and credentials. |

These APIs do not constitute an index of all companies. ATS feeds usually require the employer's board identifier, and many employers use other systems or proprietary sites. Other job sites can require contracts, credentials, attribution or prohibit reuse. A real source inventory, explicit approval, monitoring and deletion/expiry procedures are needed; do not treat a third-party board list as permission or complete coverage. The sandbox's restricted network prevents the application worker from directly reaching these ATS APIs here; page-fetch results above are separate from worker end-to-end verification.

Additional 2026-11-21 research: SmartRecruiters describes its Posting API as an unauthenticated public-data endpoint intended for customers and partners, with distinct API-key and OAuth models for other integrations: https://developers.smartrecruiters.com/docs/customer-overview. Confirm current terms and board permission rather than treating the unauthenticated endpoint as a blanket redistribution license. Third-party research identifies Workday career-site JSON endpoints as undocumented and tenant-specific; do not bypass access restrictions or rely on that research as permission. Official employer-authorized APIs or contracted feeds require per-employer/provider authorization. The undocumented Workday route is not implemented.
